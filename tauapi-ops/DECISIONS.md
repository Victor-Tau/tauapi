# DECISIONS

1. **Executor environment**: running directly on the target host as user `tau` with sudo (password-based; supplied by the user, cached for askpass in `~tau/.config/tauapi-sudo/pw` 0600, removed at handoff). `tau` is NOT added to the docker group; docker is invoked through sudo.
2. **Upstream source**: `/home/tau/new/new-api-official` clone (user statement said `/new-api-official`; the actual path is under /home/tau/new). Pinned SHA was re-fetched from GitHub into `/var/cache/tauapi/upstream` and verified; no floating main.
3. **Certificate**: no contact email provided → `certbot --register-unsafely-without-email` (GOAL §1.3). Ubuntu apt certbot 2.9.0 (single install method) with systemd `certbot.timer`; deploy hook `nginx -t && reload`.
4. **Bootstrap ordering deviation**: the certificate was issued while the host served only the ACME path and a static 503 maintenance page; no New API process existed yet, so nothing uninitialised was exposed (§13.1 satisfied).
5. **Swap**: 3.8 GiB RAM and no swap → 4 GiB `/swapfile` (fstab) for bun/rspack + Go builds; heavy builds serialized.
6. **Toolchains**: Go 1.26.10 and Bun 1.4.4 official tarballs, sha256-verified, in `~tau/.local/toolchains` for local checks; release images built in pinned-digest builder images.
7. **Backend API-only**: removed go:embed, HTML analytics injection, SetWebRouter, ServeFrontendFiles, EmbedFolder, Cache() (front-end-only). NoRoute = pluginDispatcher → RouteTag(fallback) → AccessTokenAudit → GlobalWebRateLimit → RelayNotFound (uncached JSON 404). `FRONTEND_BASE_URL` redirect mode dropped (frontend is served by Nginx on the same origin).
8. **Analytics**: not configured → not enabled. Placeholders in index.html stay inert comments.
9. **Database**: PostgreSQL 16 (supported until Nov 2028), Redis 7 (stable), images pinned by digest at deploy time.
10. **Naming (user instruction 2026-11-04)**: the split fork is **TauAPI**. Repos: `tauapi-fe` (frontend), `tauapi-be` (backend), `tauapi-ops` (ops) under `/opt/tauapi`; bare remotes `/var/lib/tauapi/git/tauapi-{fe,be,ops}.git`; runtime `/srv/tauapi`, secrets `/etc/tauapi`, backups `/var/backups/tauapi`, cache `/var/cache/tauapi`, ACME `/var/www/tauapi-acme`, Nginx `/etc/nginx/tauapi`, Compose project/DB/user `tauapi`, backend image `tauapi-be:<commit12>`, deploy lock `/run/lock/tauapi-deploy.lock`. These supersede the GOAL §2 `newapi` paths. Upstream identity (Go module `github.com/QuantumNous/new-api`, "New API" branding, QuantumNous copyright/attribution, license headers) is protected by upstream AGENTS.md and is NOT renamed.
11. **Leftover from pre-rename run**: Docker volumes `newapi_pgdata/newapi_redisdata/newapi_master_data/newapi_slave_data` were created by this task minutes before the rename (same admin credentials, no user data). They are detached and kept; removal is listed in HANDOFF as an optional cleanup.
12. **QA environment**: same scripts with `TAUAPI_ENV=qa` → compose project `tauapi-qa`, secrets `/etc/tauapi-qa`, runtime `/srv/tauapi-qa`, backends 127.0.0.1:3101/3102, Nginx `127.0.0.1:8443` with the real certificate (loopback only, no public port). A mock OpenAI-compatible upstream (compose profile `qa`, internal network only) provides SSE/WS for drills. Production never starts the mock and has no channel pointing to it.
13. **Nginx layout**: http-level `map`/`geo`/`log_format` live in `/etc/nginx/conf.d/tauapi-common.conf` (shared by prod and QA); per-env includes under `/etc/nginx/tauapi{,-qa}/` (`upstream-backend.conf` switched by `set-upstream.sh`, `proxy-backend.conf`, `security-headers.conf`). Versioned-asset `Cache-Control: immutable` is added without `always`, so 404s are never cached.
14. **Status colours kept**: success-rate strip dots (`bg-emerald/amber/red-500` in `performance-metrics/lib/format.ts`) and API-key quota colours stay as upstream; they are semantic status scales asserted by existing tests and accompanied by text/aria labels. Text-level status colours were moved to semantic tokens.
15. **Lint baseline**: upstream `bun run lint` already fails with 152 errors at the pinned SHA. The split/UI work introduces none (changed-file error count identical to the upstream versions of the same files: 31 = 31). Not "fixed" by disabling rules.
16. **Admin verification note**: upstream `GET /api/setup` short-circuits once setup is complete and reports `root_init=false`; root existence is proven by an actual admin login instead.
17. **Slave start ordering (found in QA)**: upstream caches the setup state at process start. A slave started before `POST /api/setup` keeps returning `status=false`; with round-robin Nginx the SPA then bounces between `/` and `/setup`. `bootstrap-stack.sh --with-slave` now refuses to start a slave until the master reports `status=true`, and `deploy-backend.sh` verifies `setup.status==true` on every instance before it re-enters the upstream. Production followed the safe order (init → restart master → start slave) and was never affected.
18. **QA rate limits**: the QA backend env raises CRITICAL/GLOBAL_WEB/GLOBAL_API rate limits so automated browser review (hundreds of full page loads from 127.0.0.1, each bootstrapping refresh) is not throttled. Production keeps upstream defaults (critical 20 per 20 min per client IP).
19. **Monorepo (user instruction 2026-11-04, for distribution)**: tauapi-fe, tauapi-be and tauapi-ops were merged into one Git repository at `/opt/tauapi` (remote `/var/lib/tauapi/git/tauapi.git`) with subtree merges that keep each part's full history; the per-part `.git` directories were removed after verified bundles of all three were archived in `/var/lib/tauapi/git/archive-split-20261104/`. Imports moved to `vendor/upstream-fe` / `vendor/upstream-be`; `sync-upstream.sh` uses `merge -X subtree=`. Independence of the two release units is preserved by building from `git archive main:<subdir>`. This supersedes GOAL §5/§6 "two independent repositories" at the user's request.
20. **Own release channel (user instruction 2026-11-04)**: the admin "system update" check queries `Victor-Tau/tauapi` GitHub Releases from the browser (`SYSTEM_RELEASE_REPOSITORY` in `tauapi-fe/src/features/system-update/releases.ts`) instead of QuantumNous/new-api; the user chose to make the repository public rather than add a backend proxy with a token. The target repository is admin-configurable in System settings → Operations → System maintenance (option `SystemUpdateRepository`, normalized/validated to `owner/repo` by `common.NormalizeSystemUpdateRepository`, empty = default; exposed as `system_update_repository` in `/api/status`, always the effective value). The browser snapshot cache (`system-update:v2`) and query key include the repository, so changing it triggers a fresh check. TauAPI has its own semantic version, independent of upstream: `tauapi-fe/VERSION` and `tauapi-be/VERSION` (started at `1.0.0`, bump both together). The comparison uses the backend `/api/status` version, so a release tag must equal the deployed backend `VERSION` with a `v` prefix. On upstream sync, `VERSION` conflicts always keep ours; upstream identity lives in `UPSTREAM.json`/`UPSTREAM_LOCK.json`.
